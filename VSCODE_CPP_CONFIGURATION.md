# VS Code C++ Configuration Guide

This document explains the VS Code C++ IntelliSense configuration for the Rouen project and how to troubleshoot false positive errors.

## Overview

The Rouen project uses VS Code with the C++ extension for IntelliSense support. The configuration has been optimized to work with the project's CMake build system and vcpkg dependencies.

## Configuration Files

### 1. `.vscode/c_cpp_properties.json`

This file contains four configurations for different build environments:

- **macOS-vcpkg**: Primary configuration for macOS with vcpkg dependencies
- **macOS-traditional**: Fallback configuration using system libraries
- **Linux-vcpkg**: Linux configuration with vcpkg dependencies
- **Linux-traditional**: Linux configuration using system libraries

#### Key Settings for macOS-vcpkg Configuration:

```json
{
    "name": "macOS-vcpkg",
    "includePath": [
        "${workspaceFolder}/**",
        "${workspaceFolder}/build-vcpkg/_deps/imgui-src",
        "${workspaceFolder}/build-vcpkg/_deps/imgui-src/backends",
        "${workspaceFolder}/external/imguicolortextedit",
        "${workspaceFolder}/src/helpers",
        "${workspaceFolder}/vcpkg_installed/arm64-osx/include",
        "${workspaceFolder}/vcpkg_installed/arm64-osx/include/SDL2",
        "/opt/homebrew/include",
        "/opt/homebrew/Cellar/tinyxml2/*/include",
        "/opt/homebrew/Cellar/openssl@3/*/include"
    ],
    "defines": [
        "CURL_STATICLIB",
        "DEBUG_BUILD",
        "DEBUG_ROUEN=1",
        "GL_SILENCE_DEPRECATION",
        "TINYXML2_DEBUG",
        "_FILE_OFFSET_BITS=64",
        "_GLIBCXX_DEBUG=1",
        "_LIBCPP_DEBUG=1"
    ],
    "compilerPath": "/usr/bin/clang++",
    "cppStandard": "c++23",
    "intelliSenseMode": "macos-clang-arm64",
    "compileCommands": "${workspaceFolder}/build-vcpkg/compile_commands.json",
    "configurationProvider": "ms-vscode.cmake-tools"
}
```

### 2. `.vscode/settings.json`

Contains VS Code-specific settings for C++ development:

- **C++ Extension Settings**: IntelliSense configuration, error squiggles, formatting
- **CMake Integration**: Build directory, configuration arguments, generator preferences
- **File Associations**: Proper mapping of C++ file extensions
- **Search and File Exclusions**: Optimized for build directories and dependencies

#### Critical Settings:

```json
{
    "C_Cpp.default.compileCommands": "${workspaceFolder}/build-vcpkg/compile_commands.json",
    "C_Cpp.default.cppStandard": "c++23",
    "C_Cpp.default.configurationProvider": "ms-vscode.cmake-tools",
    "cmake.configureSettings": {
        "CMAKE_TOOLCHAIN_FILE": "${workspaceFolder}/vcpkg/scripts/buildsystems/vcpkg.cmake",
        "CMAKE_BUILD_TYPE": "Debug",
        "CMAKE_EXPORT_COMPILE_COMMANDS": "ON"
    }
}
```

## How It Works

### 1. Compile Commands Integration

The configuration relies on `compile_commands.json` generated by CMake. This file contains the exact compiler commands used to build each source file, including:

- Include paths (`-I` flags)
- Preprocessor definitions (`-D` flags)
- Compiler flags (`-std=c++23`, `-stdlib=libc++`, etc.)
- System framework paths (`-F` flags)

### 2. vcpkg Integration

The project uses vcpkg for dependency management. Include paths are configured to find:

- vcpkg-installed headers in `vcpkg_installed/arm64-osx/include/`
- CMake-fetched dependencies in `build-vcpkg/_deps/`
- External project headers in `external/`

### 3. C++23 Support

The configuration is set up for C++23 standard with:
- `cppStandard`: `"c++23"`
- Compiler flags: `-std=c++2b` (clang's C++23 flag)
- macOS deployment target: `15.5` for full C++23 support

## Troubleshooting False Positive Errors

### Problem: Include Errors

**Symptoms:**
- Red squiggles under `#include` statements
- "Cannot open source file" errors
- Missing symbols from external libraries

**Solutions:**

1. **Regenerate compile_commands.json:**
   ```bash
   cd /path/to/rouen
   cmake -B build-vcpkg -DCMAKE_TOOLCHAIN_FILE=./vcpkg/scripts/buildsystems/vcpkg.cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
   ```

2. **Reload VS Code window:**
   - Press `Cmd+Shift+P` → "Developer: Reload Window"

3. **Check active configuration:**
   - Look at bottom-right status bar
   - Should show "macOS-vcpkg" configuration
   - Click to change if different

### Problem: Preprocessor Definition Errors

**Symptoms:**
- Code sections grayed out incorrectly
- Conditional compilation errors
- Platform-specific code not recognized

**Solutions:**

1. **Verify defines are set correctly** in `c_cpp_properties.json`
2. **Check CMake configuration** matches VS Code settings
3. **Rebuild compile_commands.json** after CMake changes

### Problem: C++23 Features Not Recognized

**Symptoms:**
- `std::format` marked as undefined
- C++23 syntax errors
- Modern C++ features not available

**Solutions:**

1. **Verify compiler path** points to recent clang++:
   ```bash
   /usr/bin/clang++ --version
   ```

2. **Check macOS version** (requires 13.3+ for full C++23 support)

3. **Ensure correct standard** is set in configuration

### Problem: CMake Tools Integration Issues

**Symptoms:**
- IntelliSense not updating after CMake changes
- Build targets not recognized
- Configuration provider errors

**Solutions:**

1. **Reset CMake Tools:**
   - `Cmd+Shift+P` → "CMake: Reset CMake Tools Extension State"

2. **Clean and reconfigure:**
   - Use VS Code task: "Clean vcpkg build"
   - Then: "Configure Debug with vcpkg"

3. **Check CMake Tools settings** in `.vscode/settings.json`

## Verification Steps

After configuration, verify everything works:

1. **Open a source file** (e.g., `src/rouen.cpp`)
2. **Check for errors** in Problems panel (`Cmd+Shift+M`)
3. **Test IntelliSense:**
   - Hover over functions for documentation
   - Use Go to Definition (`Cmd+Click`)
   - Try autocomplete (`Ctrl+Space`)
4. **Verify includes work:**
   - Check that `#include <imgui/imgui.h>` resolves
   - Verify vcpkg dependencies are found

## Maintenance

### When to Regenerate Configuration

- After adding new dependencies to `vcpkg.json`
- After CMake configuration changes
- After updating vcpkg baseline
- When switching between Debug/Release builds

### Regular Maintenance

1. **Keep compile_commands.json updated:**
   - Set `CMAKE_EXPORT_COMPILE_COMMANDS=ON` in CMakeLists.txt (already done)
   - Use CMake configure tasks to regenerate

2. **Update include paths** when adding new external dependencies

3. **Review preprocessor definitions** when adding conditional compilation

## Performance Tips

1. **Exclude build directories** from search (already configured)
2. **Use compile_commands.json** instead of manual include paths when possible
3. **Enable IntelliSense caching** with configuration provider
4. **Limit workspace indexing** to source directories

## Advanced Configuration

### Custom Compiler Arguments

Add platform-specific compiler arguments in `compilerArgs`:

```json
{
    "compilerArgs": [
        "-stdlib=libc++",
        "-Wall",
        "-Wextra",
        "-arch",
        "arm64",
        "-mmacosx-version-min=15.5"
    ]
}
```

### Multiple Build Configurations

Switch between Debug and Release by updating:
- CMake build type in tasks
- Preprocessor definitions in c_cpp_properties.json
- Compiler optimization flags

This configuration ensures VS Code provides accurate IntelliSense without false positive errors while maintaining compatibility with the project's modern C++23 codebase and vcpkg dependency management.
